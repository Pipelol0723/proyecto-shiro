Qué puede ir en paralelo y qué no:

- **Dentro de la Fase 1**, la tabla de olas (§3.1) ya respeta el límite de 2 PRs de agente y no junta dos PRs sobre el mismo archivo.
- **La voz** es tiempo de Pipe escuchando (Gemini y ElevenLabs) y no ocupa hueco de PR hasta el final; su PR espera a que P-03a esté fusionado (toca `README.md`).
- **Los lotes de versiones** cuentan para el límite de 2 PRs. V1 va después de P-04 PR1; V2a y el banco de pruebas, después de P-04 PR2.
- **Modelos locales**: las medidas de máquina no tocan el repo y pueden ir en cualquier semana con Ollama y Docker arriba, pero necesitan el banco de pruebas, que depende de P-04 PR2.
- **Nada** de este plan toca README.md, CLAUDE.md, AGENTS.md ni el ADR 0029 mientras P-03a esté abierto.

## 2. Lo que necesita Pipe antes de empezar

### 7.2 Riesgos de la voz nueva

- El generador no da la voz «exacta» que Pipe imagina: pueden hacer falta varias rondas.
- Ajustes que la documentación no aclara por modelo (`style` y `speed` en v4): se verifican de oído.
- Flash sin normalización de texto: cifras y fechas mal leídas.
- Free sin licencia comercial: si un día se publica audio de Shiro, revisar el plan.
- Una voz guardada depende de la cuenta: si se borra, regenerarla desde la receta y el `seed` no está garantizado.
- Usar audio de referencia de otra persona, nombrarla en el prompt o quedarse con una candidata que se le parezca de forma reconocible convierte el diseño en imitación: prohibido por la regla de §5.2.
- El README recomienda hoy un modelo deprecado (`eleven_turbo_v2_5`); lo corrige el PR de §5.8.
